# ксяосканвордми

Бесплатный русскоязычный сайт классических сканвордов. Статические HTML, CSS и JavaScript, без сервера, регистрации, API и зависимостей во время игры.

## Что есть

- Каталог из девяти заранее собранных и автоматически проверенных сканвордов: по три на каждом уровне. Размеры 9×9, 13×13 и 17×17, от 11 до 33 слов.
- Определения **в клетках**, горизонтальные и вертикальные ответы, общие буквы на пересечениях. Прямые и поворотные SVG-стрелки ведут из определения к первой букве. Сам ответ всегда идёт по прямой.
- Выбор и подсветка слова, повторный тап на пересечении для смены направления, исправление любой буквы, удаление, переход к следующей клетке и слову.
- Русская экранная и физическая клавиатуры, Е/Ё равнозначны. Стрелки перемещают курсор или меняют слово, Enter выбирает следующее слово, Backspace удаляет букву или возвращается к предыдущей пустой позиции, Delete удаляет текущую.
- Проверка ошибок, неограниченная подсказка одной буквы, подсчёт подсказок, автоматическое определение победы.
- Масштаб +/−, обзор сетки по ширине, прокрутка, перетаскивание мышью, масштабирование двумя пальцами, прокрутка к выбранной букве.
- localStorage сохраняет ответы, выбор клетки, завершение, подсказки, время, последнюю игру и новые сетки. Таймер останавливается на паузе, в диалогах и в фоновой вкладке. Прогресс общий для вкладок только при повторном открытии страницы; синхронизации между устройствами нет.
- Гибридный генератор: собственный словарь из 217 записей, ограниченный поиск связной сетки, независимая проверка перед показом. Генерация в Web Worker не блокирует интерфейс; при неудаче доступен повтор и готовый каталог.
- Интерфейс для телефона и компьютера, учёт safe-area, поддержка reduced-motion, подпапок GitHub Pages и открытия игры по ссылке.

## Запуск

Для игры ничего устанавливать не нужно. Открой опубликованный сайт по HTTPS.

Для локальной разработки нужен любой статический HTTP-сервер, например Python 3:

```sh
python3 -m http.server 4173
```

Открой `http://localhost:4173/`. Двойной клик по HTML через `file://` не подходит: браузеры ограничивают ES-модули и Web Worker. Серверная логика сайту не требуется.

## GitHub Pages

1. Помести содержимое проекта в корень нужной ветки репозитория.
2. В **Settings → Pages → Build and deployment** выбери **Deploy from a branch**.
3. Выбери нужную ветку (обычно `main`) и **/(root)**.
4. Адрес для этого репозитория: `https://vdk29.github.io/xiaoscanwordmi/`.

Все пути относительные. Сборка и npm install для публикации не требуются. `.nojekyll` отключает обработку Jekyll. Workflow `check.yml` проверяет данные и логику; сам он не публикует сайт. Если Pages уже включён для `main`, изменения появятся после слияния в эту ветку.

## Модель сканворда

Координаты отсчитываются от нуля. `clue` — координаты клетки с определением, а не отдельный список вопросов. Слово и определение берутся из единого словаря по `wordId`.

```js
{
  id: 'collection-1', title: 'На лёгкой волне', difficulty: 1,
  rows: 9, cols: 9,
  entries: [
    { wordId: 'луна', row: 4, col: 2, length: 4,
      direction: 'across', clue: [4, 1] }
  ]
}
```

Для `across` клетка определения слева от начала даёт →, над началом — поворот вниз и вправо. Для `down` клетка сверху даёт ↓, слева — поворот вправо и вниз. Валидатор допускает до двух определений в клетке, генератор резервирует отдельную клетку каждому слову для читаемости. Слова не изгибаются.

Проверяются словарь и определения, длины, границы, направления, происхождение стрелок, конфликты букв, наложения, связанность через пересечения и все непрерывные ряды букв. Нельзя добавить буквенный ряд, который не соответствует слову. Поле строится только из проверенных ответов; каждая игровая буква принадлежит ответу.

Валидатор подтверждает структурную решаемость. Языковую однозначность вопросов нельзя доказать программно: новые записи нужно редактировать вручную.

## Добавление контента

Добавь строку `СЛОВО|Краткое определение` в подходящую группу `data/words.js`. Группа задаёт тему и сложность. Не меняй значения существующих ответов без изменения ID сетки: сохранения привязаны к её координатам.

Добавь фиксированную сетку в `data/puzzles.js` или настрой новые ID, названия и зерно в `scripts/prepare-puzzles.js`. Не пересобирай существующий каталог под теми же ID после публикации: это нарушит сохранения.

```sh
npm test
npm run validate
# Только для намеренной пересборки каталога:
npm run generate
```

Node.js 20+ нужен только для разработки и тестов. Пакеты не требуются. Для больших словарей ограничивай число попыток генератора; улучшение редакционного качества и плотности возможно отдельным этапом.

## Браузерная проверка

Playwright — необязательный инструмент разработки; в сайт он не включён. При установленном Playwright и Chromium:

```sh
# В отдельном терминале:
npm run dev
# В другом:
node tests/browser-smoke.cjs
```

Можно задать `BASE_URL`, `CHROMIUM_PATH` и `PLAYWRIGHT_MODULE` для уже установленных инструментов. Сценарии проверяют каталог, уровни, ввод, пересечения, удаление, подсказки, сохранение, перезагрузку, победу, генерацию, мобильные размеры и относительные пути.

Эмуляция iPhone в Chromium не заменяет проверку в Safari на физическом устройстве. Фактически выполненные проверки и ограничения описаны в `TESTING.md`.
